🕒 Created: 2023-10-11 | Updated: 2026-11-24

std::string  ( <string> ) (C++98)

  • Inside #include <string> .

  • The string  class is a compound type. Compound types are used in the same way as fundamental types: the same syntax is used to declare variables and to initialize them. 

#include <iostream>
#include <string>

int main ()
{
  std::string my_string;
  my_string = "This is a string";
  std::cout << my_string;
  return 0;
}

Null termination

  • A std::string   always  stores a null terminator at data()[size()] .

  • The null terminator is maintained automatically.

  • That terminator is not included in size() . 

std::string s = "Hello";

s.size();       // 5
s.capacity();   // At least 5 (probably 8, or other power of 2).
s.data()[5];    // '\0'

Implementation and Encoding

  • The actual type comes from std::basic_string<T> .

  • std::string

    • std::basic_string<char>

    • Conceptually: 

    class string {
private:
    char* data;
    size_t size;
    size_t capacity;
};

  • std::wstring

    • std::basic_string<wchar_t>

  • std::u8string  (C++20)

    • std::basic_string<char8_t>

  • std::u16string

    • std::basic_string<char16_t>

  • std::u32string

    • std::basic_string<char32_t>

Initialization

  • string s can be initialized with any valid string literal, just like numerical type variables can be initialized to any valid numerical literal. 

std::string a;                   // Empty
std::string a = "Hello";         // From null-terminated C string
std::string a("Hello");          // "Hello"
std::string a("Hello", 3);       // "Hel"
std::string a(5, 'A');           // "AAAAA"
std::string a(b, 1, 3);          // "ell"
std::string a(b.begin(), b.end());

  • Copy:

    • Creates an independent string containing the same characters. It may allocate. 

    std::string a = "Hello";
std::string b = a;

  • Move:

    • Moving transfers the string's resources when possible. It generally avoids copying the character buffer. 

    std::string a = "Hello";
std::string b = std::move(a);

    • After moving, a remains valid but its contents are unspecified.

Allocation

  • A string can allocate dynamically.

  • Most modern implementations use Small String Optimization (SSO), meaning that short strings are stored directly inside the std::string  object, without a separate heap allocation. 

std::string a = "Hello";  // Usually no heap allocation
std::string b(1000, 'A'); // Usually heap allocation

  • The exact SSO capacity is implementation-dependent. The C++ standard does not guarantee a particular threshold or even require SSO.

  • So you can never know ;)

Allocation error handling

  • Allocation failure can throw std::bad_alloc .

Controlling dynamic allocations

  • You can also use std::pmr::string  (C++17) to control its memory resource.

Accessing elements

  • s[i]

    • Returns char& .

    • Access element.

    • Error handling :

      • Out-of-bounds is undefined behavior (UB).

  • s.at(i)

    • Returns char& .

    • Access element

    • Error handling :

      • Out-of-bounds throws std::out_of_range .

  • std::get<N>(s);

    • Returns char& .

    • N  is a comptime index.

    • Error handling :

      • Out-of-bounds gives a compilation error.

  • s.front()

    • Returns char& .

    • First element.

    • Error handling :

      • If the string is empty is undefined behavior (UB).

  • s.back()

    • Returns char& .

    • Last element.

    • Error handling :

      • If the string is empty is undefined behavior (UB).

  • s.data()

    • Returns char* ; being a pointer to the first element (raw C array).

    • Pointer to underlying storage.

  • s.c_str()

    • Returns const char* ; being a pointer to the first element (raw C array).

    • Pointer to underlying storage.

    • Useful for when interfacing with C: 

      printf("%s\n", s.c_str());

  • s.pop_back()

    • Doesn't allocate.

  • s.pop_front()

    • Doesn't exit.

    • Use s.erase(0, 1) .

Write

  • s.append("something")

    • Returns std::string&  as a reference of s , just to allow chaining.

    • Add a string or many character at the end. 

    s.append(" World"); // Hello World
s.append(3, '!');   // Hello World!!!

    • Allocation :

      • Grows dynamically if needed.

    • Error handling :

      • Can throw std::bad_alloc .

  • s.push_back('A')

    • Returns std::string&  as a reference of s , just to allow chaining.

    • Add exactly one character at the end.

    • Allocation :

      • Grows dynamically if needed.

    • Error handling :

      • Can throw std::bad_alloc .

  • operator+

    • Add something at the end. 

    std::string a = "Hello";
std::string b = " World";

std::string c = a + b;

c += "something";

    • Allocation :

      • Grows dynamically if needed.

    • Error handling :

      • Can throw std::bad_alloc .

  • s.insert(pos, "something")

    • Insert characters at a specified position; does not replace.

    • Returns std::string&  as a reference of s , just to allow chaining.

      • Can also return an iterator.

    • Allocation :

      • Grows dynamically if needed.

    • Error handling :

      • Out-of-bounds throws std::out_of_range .

  • s = "something";

    • Replaces all the old content by the new one.

    • It's syntax sugar for s.assign(...) .

    • Allocation :

      • If the new content is smaller than the old one, the string doesn't shrink. It just keeps its capacity.

      • If the new content is bigger than the old one, the string allocates.

    • Error handling :

      • Can throw std::bad_alloc .

  • s = 'A';

    • Replaces all the old content by the new one.

    • Allocation :

      • If the new content is smaller than the old one, the string doesn't shrink. It just keeps its capacity.

      • If the new content is bigger than the old one, the string allocates.

    • Error handling :

      • Can throw std::bad_alloc .

  • s.assign(...);

    • Replaces all the old content by the new one.

    • Returns std::string&  as a reference of s , just to allow chaining.

    • Allocation :

      • If the new content is smaller than the old one, the string doesn't shrink. It just keeps its capacity.

      • If the new content is bigger than the old one, the string allocates.

    • Error handling :

      • Can throw std::bad_alloc . 

    s.assign("hello");     // From null-terminated C string
s.assign("hello", 3);  // First 3 characters: "hel"
s.assign(5, 'x');      // "xxxxx"
s.assign(other);       // Copy another string
s.assign(other, 2, 3); // Substring: 3 chars starting at index 2
s.assign(first, last); // Iterator range

  • s.replace(pos, ...)

    • Replaces a specific portion of the string by something else. The old content outside the replacement range is preserved.

    • Allocation :

      • Allocates if pos > capacity() .

    • Error handling :

      • Out-of-bounds throws std::out_of_range .

      • Can throw std::bad_alloc . 

    std::string s = "hello world";

s.replace(6, 5, "there");
// "hello there"

  • s.erase(pos, count)

    • Remove something at pos.

    • Doesn't allocate.

    • Error handling :

      • Out-of-bounds throws std::out_of_range .

Info

  • s.size()

    • Number of elements

  • s.length()

    • Number of elements; exactly the same as s.size() , it's just an alias, basically.

  • s.empty()

    • Whether size is zero

  • s.max_size()

    • Maximum possible size.

  • s.capacity()

    • Number of elements it can hold without reallocating

Info: Comparison

  • s.compare()

    • Compare strings

    • Doesn't allocate.

  • Operator overloading, etc.

Operations: Search

  • find()  / rfind()

    • Search.

    • Doesn't allocate.

  • find_first_of()  / find_first_not_of()

    • Search for characters.

    • Doesn't allocate.

  • find_last_of()  / find_last_not_of()

    • Search for characters, backwards.

    • Doesn't allocate.

Operations

  • s.substr(from, to)

    • Returns a std::string .

    • Allocates  a new owning string.

    • Error handling :

      • Out-of-bounds throws std::out_of_range .

  • s.copy(dst, count, pos)

    • Does not append a null terminator. You must do that yourself if needed. 

    char buffer[6];
size_t copied = s.copy(buffer, 5, 0);
buffer[copied] = '\0';

    • Error handling :

      • Out-of-bounds throws std::out_of_range .

  • s.reserve(size_type new_capacity = 0)

  • s.shrink_to_fit()

  • s.resize(N);

    • Creates N  characters initialized to '\0' .

std::to_chars(...);

    • std::invalid_argument : no conversion could be performed.

Operations: Iteration 

for (char& c : s)
    c = 'X';

for (const char& c : s)
    printf("%c", c);

  • s.begin()

    • Returns iterator  or const_iterator .

    • Iterator to first element.

  • s.end()

    • Returns iterator  or const_iterator .

    • Iterator past last element.

  • s.cbegin()  / s.cend()

    • Returns const_iterator .

    • Const iterators.

  • s.rbegin()  / s.rend()

    • Returns reverse_iterator .

    • Reverse iterators.

  • s.crbegin()  / s.crend()

std::vector  ( <vector> ) (C++98)

  • Heap allocated, dynamic growth.

  • Contiguous memory

Implementation

  • LLVM libcxx - <vector>

  • Conceptually: 

template<typename T, typename Allocator = std::allocator<T>>
class vector {
public:
    // Access: `v[i]`
    constexpr       T& operator[](std::size_t pos)       noexcept;
    constexpr const T& operator[](std::size_t pos) const noexcept;

    // Access: `v.at(i)`
    constexpr       T& at(std::size_t pos);
    constexpr const T& at(std::size_t pos) const;

    // Access: `v.front(i)`
    constexpr       T& front()       noexcept;
    constexpr const T& front() const noexcept;

    // Access: `v.back(i)`
    constexpr       T& back()       noexcept;
    constexpr const T& back() const noexcept;

    // Access: `v.data(i)`
    constexpr       T* data()       noexcept;
    constexpr const T* data() const noexcept;

    // Iterator: `v.begin()`
    constexpr       T* begin()       noexcept;
    constexpr const T* begin() const noexcept;

    // Iterator: `v.end()`
    constexpr       T* end()       noexcept;
    constexpr const T* end() const noexcept;

    // Info
    std::size_t size()     const noexcept;
    std::size_t capacity() const noexcept;
    bool        empty()    const noexcept;
    std::size_t max_size() const noexcept;

    void reserve(std::size_t new_capacity);
    void shrink_to_fit();

    // Add
    void push_back(const T& value);
    void push_back(T&& value);

    // Add
    iterator insert(const_iterator pos, const T& value);

    // Add
    template<typename... Args>
    T& emplace_back(Args&&... args);

    // Remove
    void pop_back();

    // Remove
    iterator erase(const_iterator pos);

    void clear();
    void resize(std::size_t count);
    void resize(std::size_t count, const T& value);

    // Operations
    void swap(vector& other) noexcept;

private:
    // Conceptual representation, NOT actual standard members:
    T* data;
    std::size_t size;
    std::size_t capacity;
};

Initialization 

std::vector<int> v = {10, 20, 30};

v = {}; // Assigns an empty vector; may retain capacity
Implicit Memory Allocation 
std::vector<int> v; // No allocation yet

v.push_back(1); // Heap allocation (if capacity is insufficient)
v.push_back(2); // Heap allocation (if capacity is insufficient)
v.reserve(100); // Heap allocation

int x = v[0];
Choosing the allocation origin

  • Example: The vector allocates from arena, not directly from the heap.

    • Use std::pmr::vector<T>  with a std::pmr::memory_resource .

    • For a buffer you own, use std::pmr::monotonic_buffer_resource .

    • null_memory_resource()  makes allocation fail with std::bad_alloc if the buffer runs out. 

    #include <memory_resource>
#include <vector>

alignas(std::max_align_t) char buffer[1024 * 1024];

std::pmr::monotonic_buffer_resource arena(
    buffer, sizeof(buffer),
    std::pmr::null_memory_resource() // Never fall back to heap
);

std::pmr::vector<int> values(&arena);

values.push_back(42);
values.reserve(1000);

Destruction

  • Automatic destruction:

    • Standard containers follow RAII. Their destructors run automatically when they leave scope. 

    {
    std::vector<MyType> v;
    v.emplace_back();
} // v's destructor runs here

  • Manual destruction:

    • Call it destructor.

    • Not recommended, as the RAII "smartness" can cause UB afterwards: "Its destructor will run again when it leaves scope, causing undefined behavior". 

    std::vector<int> v = {1, 2, 3};
v.~vector<int>();

Accessing elements

  • v[i]

    • Access element, unchecked

  • v.at(i)

    • Access element, bounds-checked

  • v.front()

    • First element

  • v.back()

    • Last element

  • v.data()

    • Pointer to underlying storage

  • v.push_back(value)

    • Add element at the end

  • v.emplace_back(args...)

    • Add elements at the end

  • v.insert(idx, value)

    • Add element at idx.

  • v.emplace(idx, args...)

    • Add elements at idx.

  • v.assign(n, value)

    • Replaces elements with n  copies of value .

  • v.pop_back()

    • Remove element at the end.

  • v.erase(idx)

    • Remove element at idx.

  • v.erase(first, last)

    • Remove range.

  • v.clear()

    • Remove all elements.

Info

  • v.size()

    • Number of elements

  • v.capacity()

    • Number of elements it can hold without reallocating

  • v.empty()

    • Whether size is zero

  • v.max_size()

    • Maximum possible size

Operations

  • v.swap(other)

    • Swap contents.

Operations: Allocation

  • v.resize(n)

    • Change size

  • v.resize(n, value)

    • Change size, using value for new elements

  • v.reserve(n)

    • Reserve capacity

  • v.shrink_to_fit()

    • Request capacity reduction

Operations: Iteration

  • v.begin()

    • Returns iterator  or const_iterator .

    • Iterator to first element.

  • v.end()

    • Returns iterator  or const_iterator .

    • Iterator past last element.

  • v.cbegin()  / v.cend()

    • Returns const_iterator .

    • Const iterators.

  • v.rbegin()  / v.rend()

    • Returns reverse_iterator .

    • Reverse iterators.

  • v.crbegin()  / v.crend()

    • Returns const_reverse_iterator .

    • Const reverse iterators.

std::set  ( <set> ) (C++98)

  • Stores unique elements.

  • Typically implemented as a Red-Black Tree (a self-balancing binary search tree).

std::unordered_set  ( <unordered_set> ) (C++11)

  • Stores unique elements using hashing, without maintaining an order.

std::map  ( <map> ) (C++98)

  • Sorted key-value storage, typically implemented using a Red-Black Tree. 

std::map<int, int> map; // Usually no allocation yet
map[42] = 100;          // Allocates a tree node

std::unordered_map  ( <unordered_map> ) (C++11)

  • Hash table, with no guaranteed iteration order. 

std::unordered_map<int, int> map; // Usually no allocation yet
map[42] = 100;                    // Allocates bucket/node storage as needed

std::list  (C++98)

  • Linked list. 

std::list<int> list; // Usually no allocation yet
list.push_back(42);  // Allocates a node
