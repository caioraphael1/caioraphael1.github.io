Shader Models (SMs)

  • DirectXShaderCompiler/wiki/ShaderModel

  • "What GPU shader capabilities can I target?"

  • Defines:

    • Available shader stages.

    • GPU instructions and intrinsics.

    • Resource capabilities.

    • Execution features.

    • Hardware/API requirements.

  • Ex:

    • Shader Target: 

      dxc -T ps_6_6 -E main shader.hlsl

      • Compiles the main  entry point as a pixel shader targeting SM6.6.

    • Effects Framework Target: 

      fxc /T fx_2_0 Material.fx

      • Compiles an entire Direct3D 9 Effects Framework file ( .fx ) into a binary Effect object.

SM 1.x

  • 2000–2001

  • DX8

  • First programmable vertex and pixel shaders. Very limited instruction counts, registers, and capabilities.

  • Shader Targets :

    • Vertex Shader: vs_1_1

  • Effects Framework Targets :

    • fx_2_0

SM 2.0

  • 2002–2003

  • DX9

  • Much larger instruction budgets, more registers, additional arithmetic and texture operations. Introduction of high-level HLSL with DX9.

  • Shader Targets :

    • Vertex Shader: vs_2_0

    • Pixel Shader:   ps_2_0

  • Effects Framework Targets :

    • fx_2_0

SM 2.x

  • 2003–2004

  • DX9

  • Vendor-dependent extensions to SM2, including more instruction slots and capabilities. Variants include 2_a  and 2_b .

  • Shader Targets :

    • Vertex Shader: vs_2_a

    • Pixel Shader:   ps_2_a , ps_2_b

  • Effects Framework Targets :

    • fx_2_0

SM 3.0

  • 2004

  • DX9.0c

  • More powerful branching and flow control, longer shaders, more registers and additional intrinsics.

  • Shader Targets :

    • Vertex Shader: vs_3_0

    • Pixel Shader:   ps_3_0

  • Effects Framework Targets :

    • fx_2_0

SM 4.0

  • 2006

  • DX10

  • Major redesign; break from the old shader architecture.

  • Common shader architecture, geometry shaders, resource objects, constant buffers, more flexible instruction capabilities.

  • The older texture sampling model: 

sampler2D tex;

float4 color = tex2D(tex, uv);

  • Evolves to: 

Texture2D<float4> tex : register(t0);
SamplerState samp     : register(s0);

float4 color = tex.Sample(samp, uv);

  • Shader Targets :

    • Vertex Shader:   vs_4_0

    • Pixel Shader:     ps_4_0

    • Geometry Shader: gs_4_0

    • Compute Shader:   cs_4_0

  • Effects Framework Targets :

    • fx_4_0

SM 4.1

  • 2008

  • DX10.1

  • Incremental hardware and shader capability improvements.

  • Shader Targets :

    • Vertex Shader:   vs_4_1

    • Pixel Shader:     ps_4_1

    • Geometry Shader: gs_4_1

    • Compute Shader:   cs_4_1

  • Effects Framework Targets :

    • fx_4_1

SM 5.0

  • 2009

  • DX11

  • Compute shaders, tessellation, hull/domain shaders, UAVs, structured buffers, byte-address buffers, atomics.

  • Shader Targets :

    • Vertex Shader:   vs_5_0

    • Pixel Shader:     ps_5_0

    • Geometry Shader: gs_5_0

    • Hull Shader:     hs_5_0

    • Domain Shader:   ds_5_0

    • Compute Shader:   cs_5_0

  • Effects Framework Targets :

    • fx_5_0

SM 5.1

  • 2015

  • DX12

  • More flexible resource binding, descriptor arrays, resource indexing, register spaces and root-signature integration.

  • Shader Targets :

    • Vertex Shader:   vs_5_1

    • Pixel Shader:     ps_5_1

    • Geometry Shader: gs_5_1

    • Hull Shader:     hs_5_1

    • Domain Shader:   ds_5_1

    • Compute Shader:   cs_5_1

  • Effects Framework Targets :

    • No longer available, for this point forward.

SM 6.0

  • 2017

  • The previous compiler was FXC:

    • Intermediate representation: DXBC.

    • Higher-level framework for organizing shader techniques, passes and rendering state

  • The new compiler is DXC:

    • Based on LLVM/Clang.

    • Intermediate representation: DXIL.

  • Shader Targets :

    • Vertex Shader:   vs_6_0

    • Pixel Shader:     ps_6_0

    • Geometry Shader: gs_6_0

    • Hull Shader:     hs_6_0

    • Domain Shader:   ds_6_0

    • Compute Shader:   cs_6_0

  • Changes :

    • The old 'Effects framework ( technique , pass , etc.)' was replaced by 'Manage pipeline state and shader programs through the host application.'

      • Manage pipeline state and shader programs through the host application.

    • The old 'HLSL interfaces' was replaced by 'Explicit shader permutations, separate entry points or other application-level dispatch'.

    • The old 'Uniform parameters on entry functions' was replaced by 'Global resources and constant buffers'.

    • The old ' tex1D() , tex2D() , texCUBE() ' was replaced by 'Texture resource methods such as .Sample() '.

    • The old ' COLOR  semantic' was replaced by ' SV_Target '.

    • From: 

    sampler2D DiffuseTexture;

float4 PSMain(float2 uv : TEXCOORD0) : COLOR
{
    return tex2D(DiffuseTexture, uv);
}

    • To: 

    Texture2D<float4> DiffuseTexture : register(t0);
SamplerState DiffuseSampler     : register(s0);

float4 PSMain(float2 uv : TEXCOORD0) : SV_Target
{
    return DiffuseTexture.Sample(DiffuseSampler, uv);
}

  • Wave intrinsics, 64-bit integer arithmetic.

  • Microsoft introduced a new compiler architecture .

  • Designed to maintain substantial compatibility with SM5.1 while introducing DXIL and new GPU capabilities.

  • Wave intrinsics expose operations across lanes executing together: 

WaveActiveSum(value);
WaveActiveMax(value);
WaveActiveAllTrue(condition);
WaveReadLaneAt(value, laneIndex);

  • Exposes GPU execution behavior to the shader programmer.

  • Think reductions, scans, voting, lane communication, and implementing parallel algorithms without necessarily using groupshared memory.

  • Shader Targets :

  • 2019

  • Variable Rate Shading support, packed low-precision dot-product operations, raytracing library sub-objects.

SM 6.5

  • 2020

  • DXR 1.1, inline ray queries, sampler feedback, mesh shaders, amplification shaders, additional wave intrinsics.

  • Amplification shaders ( as_6_5 ):

    • generate and distribute mesh-shader work.

  • Mesh shaders ( ms_6_5 ):

    • generate geometry directly instead of using the traditional vertex/input-assembly pipeline.

  • Shader Targets :

    • Vertex Shader:   vs_6_5

    • Pixel Shader:     ps_6_5

    • Geometry Shader: gs_6_5

    • Hull Shader:     hs_6_5

    • Domain Shader:   ds_6_5

    • Compute Shader:   cs_6_5

SM 6.6

  • 2021

  • Dynamic resource indexing, 64-bit atomics, derivatives in compute/mesh/amplification shaders, configurable wave size and additional intrinsics.

  • You can access resources directly from descriptor heaps: 

Texture2D<float4> tex =
    ResourceDescriptorHeap[textureIndex];

SamplerState samp =
    SamplerDescriptorHeap[samplerIndex];

float4 color = tex.Sample(samp, uv);

  • Shader Targets :

    • Vertex Shader:   vs_6_6

    • Pixel Shader:     ps_6_6

    • Geometry Shader: gs_6_6

    • Hull Shader:     hs_6_6

    • Domain Shader:   ds_6_6

    • Compute Shader:   cs_6_6

SM 6.7

  • 2022–2023

  • Advanced texture operations, programmable sampling offsets, writable MSAA textures, quad operations and helper-lane controls.

  • Shader Targets :

    • Vertex Shader:   vs_6_7

    • Pixel Shader:     ps_6_7

    • Geometry Shader: gs_6_7

    • Hull Shader:     hs_6_7

    • Domain Shader:   ds_6_7

    • Compute Shader:   cs_6_7

SM 6.8

  • 2024

  • Work Graphs, expanded comparison sampling and configurable wave-size ranges.

  • Work Graphs introduce GPU-driven execution through interconnected shader nodes.

  • Instead of having the CPU explicitly schedule every subsequent GPU operation, shader execution can generate further GPU work.

  • Shader Targets :

    • Vertex Shader:   vs_6_8

    • Pixel Shader:     ps_6_8

    • Geometry Shader: gs_6_8

    • Hull Shader:     hs_6_8

    • Domain Shader:   ds_6_8

    • Compute Shader:   cs_6_8

SM 6.9

  • Feb 2026

  • Long vectors (up to 1024 elements), improved 16-bit floating-point operations, Opacity Micromaps and Shader Execution Reordering.

  • HLSL traditionally supported vectors up to four elements: 

float4 value;

  • SM6.9 extends the vector model to 5–1024 elements, opening up more direct expression of machine-learning and linear-algebra workloads.

  • SM6.9 makes native 16-bit shader operations, wave operations, and 64-bit integer operations required features for conforming implementations, whereas these had previously been optional capabilities

  • Shader Targets :

    • Vertex Shader:   vs_6_9

    • Pixel Shader:     ps_6_9

    • Geometry Shader: gs_6_9

    • Hull Shader:     hs_6_9

    • Domain Shader:   ds_6_9

    • Compute Shader:   cs_6_9

SM 6.10

  • Apr 2026

    • Not a production baseline yet.

    • Preview: Linear algebra/matrix APIs, group-wave indexing, variable groupshared memory and new raytracing intrinsics.

HLSL 2015

  • Legacy language version supported by FXC.

  • The Effects Framework predates the modern year-based HLSL language versioning.

HLSL 2016

  • Initial DXC-compatible language version; 64-bit integer types and related vector/matrix types.

HLSL 2017

  • enum and enum class.

HLSL 2018

  • Explicit-width float and integer types (16, 32 and 64 bits).

HLSL 2021

  • Templates, bitfields, operator overloading, C++-style function overloading and scalar short-circuit logical operations. 

template<typename T>
T Square(T value)
{
    return value * value;
}
