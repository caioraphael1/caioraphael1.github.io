Import

🕒 Created: 2023-07-26 | Updated: 2026-11-02

  • When dragging and dropping a .blend  file inside another .blend  file, you'll be prompted with:

Copy / Paste

  • You can copy elements from one .blend  file to another, just by using ctrl+c and ctrl+v.

  • Everything is local; unlinked-copy.

Append

  • Just a "copy / paste".

  • Everything is local, independent from the source.

  • No instancing:

    • Dragging a material into the scene three times will result in three independent copies.

    • Dragging an object into the scene three times will also result in three independent copies.

Link

  • Brings an instance from another .blend  file, and every time you make a change to the original file, the instance will be updated.

  • How linked data looks :

  • "Linked Data. Not Editable"

    • .

  • "Library Override Data. Editable, almost".

    • .

    • The data can be edited, but will revert to the original data once the file is reloaded.

    • Edits made after a Library Override are not saved anywhere, so this is only useful for testing; as changes are not saved.

    • Despite this, you can still make Poses and create new animations (old ones cannot be modified).

    • The idea is that you cannot modify the data, but you can animate the data.

      • These new animations are stored in the current Blender file, not in the source file.

    • A Collection is instanced as an Empty.

      • To see its contents, you have to make a Library Override .

  • Good workflow :

    • "An animator would work on a linked version of the file, while a modeler / rigger would work on the original file."

    • "A level designer would work on a linked version of the file, with the low-poly mesh, while the modeler would work on the original file."

    • You should link Collections , not just anything.

      • "You can easily add or remove assets from a Collection. Objects can only store their own data."

      • An Object cannot even be moved.

    • .

      • "Use a master collection", etc.

    • .

      • Name your collections as obviously as possible, to not link wrong collections.

      • My Master Collection is fully capitalized.

  • Asset is a Collection, importing with Instance Collection :

    • The collection object can be moved around, etc.

  • (No) Asset is a Collection, importing without Instance Collection :

    • Cannot move any meshes, nor the collection. They stay right where they were in the source file.

  • (No) Asset is an Object :

    • Cannot move the asset around in the destination file, as the position is a linked parameter.

    • The option for Instance Collection doesn't matter, it will be the same.

Pack

  • TLDR :

    • My interpretation of this is "Append and make locally linked, without external dependencies".

    • If the source changes, the destination will NOT change.

  • The actual name is "Packed Linked Data".

  • Imports the asset as linked data and immediately packs it into the current blend-file. This ensures that the asset remains available even if the original library data is modified or becomes unavailable.

  • Useful for maintaining self-contained files that do not rely on external asset library paths.

  • Affected by "Instance Collections when Linking", but not by "Instance Collections when Appending".

My method for handling Objects / Collections / Meshes

  • (2026-10-17)

  • Philosophy :

    • Import the raw data as local data, or as a reference, and just use this raw data.

  • Creating the asset :

    • The asset can be created as an Object or as a Collection, it doesn't matter.

    • You are not moving the imported asset anyway, you are just using the asset to get the underlying raw data.

  • Importing the asset :

    1. Append with or without a Collection, without Instance Collection.

      • The idea is to make the data local and avoid the library nightmare.

      • "What about if you want to change the library and make the changes be reflected in the other file?"

        • Just import the asset again with the same "Append without Instance Collection", and use the new local data as the new data for the asset you were using locally. For example, just change from the old mesh to the new appended mesh, done.

        • This has to be done manually, of course, but it's much less prone to any headaches, and you have more control.

    2. Link with or without a Collection, without Instance Collection.

      • Same idea as the append one: you are just importing the asset once, and then using it's data locally, but this time, the data is stored externally.

    • Why not the other options? :

      • The other options are extremely

      • The options above are less "automated" or whatever, but they are much less convoluted, giving you more obvious control, differently from the other options that require you to have a "PhD in Blender's Mechanics of Importing Assets" to untangle the mess.

      • "What about packing?": It's so not intuitive, and whatever is happening under the hood, you can achieve the same with Append or Link, so no.

Catalog

  • It's basically a virtual folder for organizing the assets inside a Asset Library.

  • File system folders don't do anything to a catalog.

  • An asset can be assigned to a single catalog at a time.

  • New catalogs can be created in the Asset Browser through Header ‣ Catalog ‣ New Asset Catalog. Once the catalog is created you can double LMB on its name in the Source List region of the editor to give the catalog a more descriptive name. Catalogs can also be created in this region by clicking the plus icon found at the top of the Tree View.

  • Each catalog consists of a catalog path, a UUID, and a simple name.

  • (2026-09-08)

    • This is a reeeaaaaally convoluted feature. As always, something simple, made confusing.

  • TLDR :

    • Each asset has a field inside its file that associates a Catalog UUID where this asset belongs.

    • A catalog UUID is defined inside the blender_assets.cats.txt  file, on the root of the Asset Library.

    • The "Simple Name" is just a human readable name of the catalog, that never shows up in the UI.

      • This name is never updated inside the asset. Once you select a new UUID Catalog for that asset, the Simple Name will update automatically.

    • Ex :

      • Creating a Brushes  catalog, creates this entry inside the file: 170b451e-72f4-4a20-8fbe-9de910671855:Brushes:Brushes .

Creating new Catalogs

  • A new catalog has to be created inside the Current File section.

  • If a catalog is added, while the file is inside a Asset Library folder/subfolder, then that catalog will be added to the blender_assets.cats.txt  of that Asset Library.

Assigning assets to a catalog

  • Asset metadata can only be edited for assets in the current .blend  file, otherwise, you'll be shown a read-only view.

  • If Blender can edit the asset metadata, just drag an asset into a catalog.

Dealing with many .blend  file

  1. Merge all files into one:

    • Open one of them, drag and drop the others one by one inside the first one, selecting "append" and appending the assets.

blender_assets.cats.txt  file

  • Creating a new catalog on blender's interface will make so a blender_assets.cats.txt  file is created side by side with the .blend  file containing the asset.

  • There can only be one  of this file for a whole Asset Library, and it should be placed on the root of the Asset Library.

  • Catalog Path :

    • The path of a catalog determines where in the catalog hierarchy the catalog is shown. Examples are Characters/Ellie/Poses/Hand  or Kitbash/City/Skyscrapers .

    • Catalog paths follow the following rules:

      • All paths are absolute; there is no difference between /a/b and a/b.

      • Only / as separator (no ; think less filesystem path and more URL).

      • Not empty (it’s required for a valid catalog).

      • No empty components (so not a//b; a/b is fine).

      • Invalid characters: :, .

      • Paths are always interpreted as UTF-8.

  • UUID :

    • Each catalog has a UUID, which is normally hidden from the user interface (enable Developer Extras and the experimental Asset Debug Info option to see them). This is what is stored in the asset, and what determines the «identity»  of the catalog. As a result, a catalog can be renamed or moved around (i.e. you can change its path), and all assets that are contained in it will move along with it. This only requires a change to the catalog itself, and not to any asset blend-file.

  • Simple name :

    • Each catalog has an optional simple name. This name is stored along with the UUID in each asset. The purpose is to make it possible for humans to recognize the catalog the asset was assigned to, even when the catalog definition file (see below) is lost.

    • Like the UUID, the simple name is normally hidden from the user interface. Enable Developer Extras in the interface preferences to make it visible in the Asset Browser.

  • Ex : 

    # This is an Asset Catalog Definition file for Blender.
#
# Empty lines and lines starting with `#` will be ignored.
# The first non-ignored line should be the version indicator.
# Subsequent lines are of the format "CATALOG_UUID:catalog/path/for/assets:simple catalog name"
