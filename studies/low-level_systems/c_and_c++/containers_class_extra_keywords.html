Containers: Class - Extra Keywords

🕒 Created: 2023-10-11 | Updated: 2026-11-24

explicit

For Class constructors (C++98)

  • Direct initialization is allowed, but copy initialization is not, as that would require an implicit conversion.

  • Without explicit : 

    struct String {
    String(const char* s) {}
};

void print(String s);

int main() {
    print("hello"); // OK
}

  • With explicit : 

    struct String {
    explicit String(const char* s) {}
};

void print(String s);

int main() {
    print("hello");          // Error
    print(String("hello"));  // OK
}

    struct Vec2 {
    explicit Vec2(float v)
        : x(v), y(v) {}

    float x, y;
};

Vec2 a(5.0f);      // OK
Vec2 b = 5.0f;     // Error

  • Conditional explicit  (C++20):

    • The constructor is explicit only if the constant expression evaluates to true. 

    template<typename T>
explicit(sizeof(T) > 4)
MyType(T);

For Class conversion operators (C++11) 

explicit operator bool() const;

  • Without explicit : 

    struct File {
    operator bool() const {
        return true;
    }
};

File f;

if (f) { }      // OK
bool b = f;     // OK
int x = f;      // Also possible through bool -> int

  • With explicit : 

    struct File {
    explicit operator bool() const {
        return true;
    }
};

File f;

if (f) { }                 // OK (special case)
bool b = f;                // Error
bool b2 = static_cast<bool>(f); // OK

concept  (C++20)

  • Defines a reusable compile-time constraint.

  • It makes template requirements part of the interface instead of burying them in implementation details. 

template<typename T>
concept Numeric = std::is_arithmetic_v<T>;

template<Numeric T>
T Add(T a, T b)
{
    return a + b;
}

std::enable_if  (C++11)

  • A library template that conditionally enables declarations based on a compile-time boolean.

  • Enable/disable template overloads. 

template<typename T>
std::enable_if_t<std::is_integral_v<T>, void>
Process(T value)
{
}

  • If the condition is false, substitution fails and this overload is discarded.

  • This technique is known as "SFINAE: Substitution Failure Is Not An Error".

  • It predates concepts and is still found in older codebases.

export

For Class templated (C++98)

  • This was abandoned.

  • C++98:

    • Exported templates

    • The feature failed, as it turned out to be extremely difficult to implement.

    • A compiler had to:

      • track template definitions across translation units,

      • instantiate templates later,

      • manage complex dependency information.

    • Almost no compiler implemented it.

  • C++11:

    • The original export  keyword remained reserved, but the exported-template feature was effectively dead.

  • C++20:

    • Completely repurposed export  to export names from a module.
